Open source: nb-probe

The scanner behind the Quick Scan. Free, MIT licensed, and yours to run. Supabase is the first target.

What it catches

The most common leak in vibe-coded apps is user A reading user B's rows through a perfectly valid API call. Normal scanners can't flag it because they don't know who owns what. nb-probe creates two users in your app, inserts one row for each, and checks whether A can read or change B's row.

Eight checks

Anonymous read, cross-user read and write, self-promotion to admin or a paid plan, closed-signup bypass, secrets and source maps in the JS bundle, unsigned webhooks, and LLM endpoints that accept anyone or any model. Each failure comes with a curl repro and the fix.

Only your own apps

It refuses to scan until your app serves a token at /.well-known/neural-breach, so it only runs against apps you control. JSON output and exit codes for CI.

npx nb-probe token   # serve this at /.well-known/neural-breach
npx nb-probe scan --url https://app.example --token "$NB_TOKEN" \
  --supabase-url "$NB_SUPABASE_URL" --anon-key "$NB_ANON_KEY"

A pass means the probe did not observe the failure. It does not mean the app is safe. Run it against staging: it inserts rows and deletes them before it exits.

What we usually find

Illustrative examples of issue types common in vibe-coded apps, not client data.

CRITICAL

Row-level security off

Any signed-in user can read or edit every other user's rows by calling the database API directly.

CRITICAL

Admin key in the browser

A service-role or secret API key shipped in the front-end bundle, giving full database or billing access.

HIGH

Missing ownership checks

/api/invoices/123 returns anyone's invoice: the route checks login, not ownership.

HIGH

Unsigned payment webhooks

The Stripe webhook trusts any request, so a forged call can unlock a paid plan.

HIGH

Prompt injection in AI features

User text can make your AI feature reveal its system prompt, other users' data, or call tools it shouldn't.

MEDIUM

Public storage buckets

Uploaded files, including IDs and invoices, are reachable by guessable URL.

FAQ

Why is a security review called Neural Breach?

Because finding the breach is the job. We think like an attacker on paper, inside your code, so nobody gets to do it for real. We are strictly defensive: we only review apps whose owners hire us.

Is this a penetration test?

No. A review is a code and configuration review from the inside, and we do not attack your running app. The Quick Scan does send requests to your live app, but only after you add the ownership token, and only with two test users it creates for the scan and removes afterward. If you need a formal pentest for a customer or auditor, we'll tell you.

What's the difference between the Quick Scan and a review?

The Quick Scan is automated. It runs nb-probe's eight checks against your live app and tells you which failed, with a curl repro and the fix for each. A pass means the probe did not observe the failure, not that the app is safe. A review is a senior engineer reading your code, so it finds what a scanner can't: broken business logic, risky AI features, payment flows, and the context to rank what matters. A failed Quick Scan is a good reason to book one.

What counts as a "small app" for the $199 Vibe tier?

One repo, one small product, no payments and no multi-tenant roles yet. Think a weekend build about to get its first users. If you have Stripe, teams, or admin roles, start at Express.

Does it work if my app wasn't vibe-coded?

Yes. The method is the same; vibe-coded apps are simply the ones that ship with the least review.
